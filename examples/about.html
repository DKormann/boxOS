Small programs.
Clear boundaries.

BOXOS is an experimental runtime for immutable code, isolated mutable state, and explicitly owned asynchronous effects.

Description

Five pieces, one small model.

01 / Blobs

Exact immutable bytes identified by their content. A blob has no intrinsic type.

02 / Boxes

An immutable method table attached to one isolated mutable state namespace.

03 / Methods

Named entry points that compute, enter atomic blocks, and coordinate effects.

04 / Tasks

Eager asynchronous work owned by an invocation. Nothing is accidentally detached.

05 / Accounts

Public keys with signing authority, a strict nonce, and fuel for bounded work.

The rule

State that must change atomically belongs in one box. Boxes never share transactions.

Developer reference

The method model.

Method bindings

Each method receives ctx for invocation capabilities and input for one BOXOS value.

ctx.atomic(function update(tx) {
  let count = tx.state.public.get("count") || 0;
  tx.state.public.set("count", count + 1);
  return count + 1;
});

State

Private and public state both provide synchronous exact-key operations inside an atomic block.

tx.state.private.get(key)
tx.state.private.has(key)
tx.state.private.set(key, value)
tx.state.private.delete(key)

Effects

Effects are forbidden inside atomic blocks. Outside them, requests and cross-box calls return invocation-owned Tasks.

let response = await ctx.request(url, options);
let result = await ctx.call(box, method, input);
let page = await ctx.hostPage(blobId);
let valid = ctx.verify(publicKey, message, signature);

Values

Values are finite trees of null, booleans, finite numbers, strings, arrays, and plain string-keyed objects.
